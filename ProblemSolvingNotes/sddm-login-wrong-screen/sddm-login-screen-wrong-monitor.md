# SDDM Login Screen Shows on Wrong Monitor

## Problem

When logging out of the Hyprland session, SDDM's login screen appears only on the external monitor.
When no external monitor is connected, all screens are blank — forcing blind password entry.

## Symptoms

- Internal laptop screen (eDP-1) is black/blank during SDDM greeter
- External monitor (connected via NVIDIA GPU) shows the login prompt
- With no external monitor: nothing visible at all
- After logging in blindly, the Hyprland session displays correctly on eDP-1

## Investigation

### System Details

- **Display Manager:** SDDM (Wayland mode for user session)
- **Session:** Hyprland via UWSM
- **GPU:** NVIDIA Quadro P1000 + Intel integrated GPU (Optimus/hybrid)
- **Config path:** `~/.config/hypr/monitors.conf` has `monitor = eDP-1, 1920x1080@60, 0x0, 1`
- **SDDM configs:** `/etc/sddm.conf.d/`

### Root Cause

**1. Broken `optimus-manager` config remnants**

The file `/etc/sddm.conf.d/optimus-manager.conf` contains:

```
[Wayland]
CompositorCommand=/usr/bin/optimus-manager-wayland-launcher %session
```

This binary **does not exist** on the system. Because this file is loaded last alphabetically, it overrides the working compositor command from `/etc/sddm.conf.d/10-wayland.conf`:

```
[Wayland]
CompositorCommand=start-hyprland -- --config /usr/share/sddm/hyprland.conf
```

When SDDM tries to start the Wayland display server for the greeter, the compositor binary is missing → **fails to start** → likely falls back to X11.

**2. Broken X11 setup script**

`/usr/share/sddm/scripts/Xsetup` (generated by EnvyControl) contains:

```sh
xrandr --setprovideroutputsource "modesetting" NVIDIA-0
xrandr --auto
```

This tries to configure monitors through the NVIDIA provider. On this Optimus system:

- eDP-1 (laptop screen) is driven by the Intel iGPU — the NVIDIA provider source doesn't map to it
- External monitors connected via the NVIDIA GPU work fine
- Result: eDP-1 stays black/blank

**3. No monitor configuration in SDDM's Hyprland config**

`/usr/share/sddm/hyprland.conf` has no `monitor =` lines — Hyprland auto-detects, but this doesn't help when SDDM falls back to X11.

### Flow on Logout

```
User logs out of Hyprland
  → SDDM detects session ended
  → SDDM reads configs (optimus-manager.conf overrides Wayland compositor)
  → Tries: start-hyprland -- custom launcher → binary missing → FAIL
  → Falls back to X11 display server
  → Runs Xsetup → xrandr NVIDIA commands → eDP-1 stays blank
  → External monitor (NVIDIA) → login screen visible
  → No external → nothing visible
```

## Fix Applied (2026-06-30)

### Changes Made

**1. Disabled broken `optimus-manager` SDDM config**

- Renamed `/etc/sddm.conf.d/optimus-manager.conf` → `/etc/sddm.conf.d/optimus-manager.conf.disabled`
- This file referenced a non-existent binary `optimus-manager-wayland-launcher` which overrode the working compositor command from `10-wayland.conf`
- With it disabled, `10-wayland.conf` takes effect: `start-hyprland -- --config /usr/share/sddm/hyprland.conf`

**2. Added explicit monitor config to SDDM's Hyprland**

- Edited `/usr/share/sddm/hyprland.conf`
- Added `monitor = eDP-1, 1920x1080@60, 0x0, 1` before the catch-all rule
- The catch-all `monitor = , preferred, auto, auto` handles any external monitors
- This ensures eDP-1 (laptop screen) is always explicitly enabled

**3. Cleaned up EnvyControl Xsetup script**

- Rewrote `/usr/share/sddm/scripts/Xsetup` to a harmless stub
- The old script had NVIDIA-specific `xrandr` commands that didn't map the Intel iGPU output (eDP-1)
- This was the X11 fallback path that was actively preventing eDP-1 from working

### What Changed (Summary)

| Before | After |
|--------|-------|
| SDDM tried non-existent Wayland compositor → fell back to X11 | SDDM uses working Wayland compositor |
| X11 Xsetup script disabled eDP-1 via xrandr | Xsetup is clean (Wayland preferred anyway) |
| SDDM Hyprland config had no monitor settings | SDDM Hyprland explicitly enables eDP-1 first |

### Verification

- [ ] Log out of Hyprland → SDDM greeter shows on eDP-1 (laptop screen)
- [ ] Connect external monitor → log out → greeter shows on both screens
- [ ] Disconnect external → log out → greeter shows on eDP-1

### Rollback (if needed)

```bash
# Restore optimus-manager config
sudo mv /etc/sddm.conf.d/optimus-manager.conf.disabled /etc/sddm.conf.d/optimus-manager.conf

# Restore original Xsetup
sudo cp /usr/share/sddm/scripts/Xsetup.bak /usr/share/sddm/scripts/Xsetup

# Restore original SDDM hyprland config
sudo tee /usr/share/sddm/hyprland.conf << 'EOF'
# Minimal Hyprland config for the SDDM Wayland greeter.
misc {
  disable_hyprland_logo = true
  disable_splash_rendering = true
  force_default_wallpaper = 0
}
animations {
  enabled = false
}
EOF
```
